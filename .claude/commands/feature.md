# 機能開発ワークフロー

要件・仕様が確定した後、以下の手順で機能開発を進めてください。

## ステップ 1: 機能開発ブランチ作成

`main` から最新を取得してブランチを切る。

```bash
git fetch origin main
git checkout -b feature/<機能名> origin/main
```

ブランチ名は `feature/` プレフィックスを付け、内容が分かる英語の短い名前にする（例: `feature/history-modal`）。

## ステップ 2: 機能開発

- コンポーネント・ロジックを実装する
- 型定義（`src/types/index.ts`）から先に固めると手戻りが少ない
- Firestoreを扱う場合は `firestore.rules` のサブコレクション対応も忘れずに

## ステップ 3: テスト

ユーティリティ関数を変更・追加した場合は必ずテストを実行する。

```bash
npm test
```

テストがすべてパスすることを確認する。UIの変更を含む場合は `npm run dev` で動作確認も行う。

## ステップ 4: README.md 更新

機能追加・変更によってユーザー向けの説明が必要な場合は `README.md` を更新する。
- 新機能の概要
- 操作方法（必要な場合）

変更がない場合はスキップしてよい。

## ステップ 5: コミット & プッシュ

```bash
git add <変更ファイル>
git commit -m "<変更の概要（日本語可）>"
git push -u origin <ブランチ名>
```

コミットメッセージは「何をしたか」より「なぜしたか」を重視する。

## ステップ 6: PR 発行

GitHub MCP ツールで PR を作成する。

- タイトル: 70文字以内、変更内容が分かるもの
- 本文: 変更内容の箇条書き + テスト手順
- base ブランチ: `main`

## ステップ 7: レビュー & マージ（ユーザー対応）

PR 作成後はユーザーにレビュー・マージを依頼して完了。
マージされたら、必要に応じて Firebase Console または Firebase CLI でルール等をデプロイする。
